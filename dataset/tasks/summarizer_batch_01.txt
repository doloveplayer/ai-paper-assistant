II. LITERATURE REVIEW
Vehicle detection in normal weather is evaluated extensively
using single-stage and two-stage deep learning algorithms on
diverse datasets. A research gap still exists for efficient and
cost-effective vehicle detection in foggy weather conditions.
The YOLO series of algorithms has emerged as a potential
solution for detecting vehicles at higher inference speeds with
reasonable accuracy. The YOLO series of algorithms has
evolved into many versions. The YOLO version 11 (YOLO-
V11) architecture is mainly based on YOLO version 5 (YOLO-
V5) and YOLO version 8 (YOLO-V8) algorithms.
The YOLO-V11 network architecture comprises a backbone
network, neck, and head. The backbone of YOLO-V11 con-
sists of convolutional layers, C3k2 (faster implementation of
Cross Stage Partial (CSP) bottlenecks with 2 convolutional
layers) layers, Spatial Pyramid Pooling Fast (SPPF) module,
and C2PSA (2 convolutional layers with Position Sensitive
attention (PSA) mechanism) module. The backbone of YOLO-
V11 efficiently extracts the spatial features for enhanced fea-
ture extraction, processing, and pooling of features at diverse
scales. The neck aggregates the features using bottom-up and
top-down paths towards the detection head. The detection
head detects the objects using pre-defined anchor boxes. The
main difference between YOLO-V5, YOLO-V8, and YOLO-
V11 is bottleneck modules. YOLO-V5 contains C3 bottle-
neck modules, YOLO-V8 contains C2f modules, and YOLO-
V11 contain C3k2 modules. The architectural diagram of the
YOLO-V11 algorithm is illustrated in Fig. 2.
A comprehensive overview of the related work is discussed
in this section. A diverse set of experiments was performed to
evaluate the vehicle detection efficiency and cost-effectiveness
of YOLO-V5, YOLO-V5 variants, and YOLO-V8 algorithms
on DAWN and FD datasets. The proposed YOLO-V5 variants
were based on Common Block Attention Module (CBAM),
Normalized Attention Module (NAM), and Simplified Atten-
tion Module (SimAM) modules integrated into the backbone
of the baseline YOLO-V5 algorithm. They also evaluated the
performance of YOLO-V5l with the Feature Pyramid Pooling
(FPN) path [5].
Another study evaluated the performance of the YOLO-V5

5.3.2. Comparison of Different Implementations of Our ColTeaching
We further investigated three implementations of ColTeaching to select an optimal
conﬁguration of the deraining feature extractor. The ﬁrst implementation, called “Baseline
w Conv_1”, adopts the ﬁrst two convolution blocks of the detection subnetwork as the
deraining feature extractor. The second implementation, called “Baseline w Conv_2”,
adopts one more convolution block to learn deeper features. We continue exploring the
deeper features as the deraining feature extractor with the ﬁnal implementation, called
“Baseline w Conv_3”, which uses all convolution blocks. Table 3 compares the DroneDet
accuracy of CoDerainNet with different convolution blocks. The experimental results
demonstrate that “Baseline w Conv_1” can obtain the best DroneDet performance.
To interpret the improved performance, note that, compared with Conv_2 and Conv_3,
features extracted by Conv_1 have the maximum resolution and hence contain the richest
spatial details. Deraining features extracted with the deeper convolutional blocks (Conv_2
or Conv_3) contain less amount of spatial details due to their low resolution. The visibility
enhancement for input images of these features is limited, which leads to the poor quality
of features for the DroneDet Subnetwork.

4.2. Training Settings
We employ the SGD optimizer with an initial learning rate of 1 10−2 to train our
proposed ODFC-YOLO model. The total training epochs and batch size are to 100 and 32,
respectively and the learning rate is adjusted dynamically during training using a cosine
annealing decay strategy. Additionally, we do not use image augmentation techniques,
commonly used in YOLO-based models, since these techniques would increase the difﬁculty
of reconstructing images for the dehazing subnet, resulting in poor performance of the
object detector. We set the image size for training and testing to 640 640 pixels.
